# 判断依据完善与跨平台插件设计

依据：开发者于 2026-11-01 要求“按照建议完善 constitution-layer”，并明确要求支持安装到 Claude Code 和 Codex。保留 `SPEC-KIT-COMPARISON.md` 作为原始调研快照。

## 目标与范围

修复报告中的规则矛盾与项目级退出缺口；增加可安装的 Claude Code、Codex 原生插件清单；提供最小决策证据、修订记录和可重复的行为评估材料。继续保持建议器定位，不增加工具拦截，不复制 Spec Kit 或 superpowers 的流程。

## 方案选择

1. **共用现有插件目录，平台清单独立（采用）**：DSH 保留根 bundle；CodeBuddy、Claude、Codex 使用 `plugins/constitution-layer` 内同一技能和注入脚本。平台市场与清单分别描述各自入口。维护成本低，安装后的脚本不依赖插件目录之外的文件。
2. 每个平台复制一份完整插件：便于独立发布，但技能、判据与脚本容易漂移。
3. 改用统一 CLI 安装器、修改用户全局配置：引入更多文件所有权、迁移与卸载问题，当前没有必要。

## 范围解析

从工作目录向上扫描，记住遇到的第一份判断依据所在目录，但继续检查祖先退出标记直到最近的 `.git` 或文件系统根。范围内任一退出标记优先；最近 `.git` 之外的标记与依据不可继承。未关闭时仍使用最近的一组依据，不拼接多层文件。嵌套 Git 仓库是独立项目。

DSH 与独立 CJS hook 保持相同判据，由共享场景测试验证。此轮不为消除两个简单函数而重构整个包布局。

## 平台接入

- Claude Code：根 `.claude-plugin/marketplace.json` 指向共享插件；插件 `.claude-plugin/plugin.json` 使用标准 `skills/` 与 `hooks/hooks.json`。支持本地 `--plugin-dir` 和市场安装。
- Codex：根 `.agents/plugins/marketplace.json` 指向共享插件；插件 `.codex-plugin/plugin.json` 显式声明 `skills/` 与 `hooks/codex.json`。采用官方仍支持的兼容清单，避免引入未验证的可移植清单迁移。
- 共用 `session-start.cjs` 的 stdin `cwd` 输入与 `hookSpecificOutput.additionalContext` 输出。Codex 配置使用官方 `${PLUGIN_ROOT}`，Claude / CodeBuddy 保留 `${CLAUDE_PLUGIN_ROOT}`。
- SessionStart 不列举 source 白名单，覆盖宿主触发的启动、恢复、压缩和 fork；不承诺每一模型请求重读。DSH 的每次装配重读另行说明。
- 安装与信任分开。Codex 首次运行 hooks 需要用户在宿主 `/hooks` 中审阅信任；不自动绕过或更改全局配置。

## 治理与技能

本项目身份调整为独立判断依据层，可组合外部流程。重复问题可以依据已确认决策修复实现，但不得据此自动增改治理文件。明确智能体可以转录开发者已确认的文本，不能自行推断或起草价值条款。

既有两份依据且无冲突时直接进入常规任务；初始化访谈仅用于缺失依据或开发者明确请求修订。注入存在必须同时检查两份 BEGIN 标记，避免“仅宪法已注入”误判齐备。补齐时保留现有文件与开发者已决定的内容。

心智模型用于合法方案之间排序；只有明确适用的取舍被无理由违背，或导致返工与偏离时才提升为需处理意见，不把一般偏好全部归为红线。

## 证据与修订

审查输出使用“规则位置与原文 / 候选方案与取舍 / 决定 / 验证证据”四项，不自动生成新的永久文件。治理修订由显式授权驱动，在根 `CHANGELOG.md` 留下本轮范围、原因与验证结果。

增加可重复的行为场景与对照运行说明；自动测试验证注入判据与平台包装，不伪称已经完成模型行为效果评估。

## 验证

先加入失败测试：根退出标记与子目录依据、Git 指针文件、嵌套仓库隔离、最近依据选择。再修改两套实现。

平台测试从各市场读取清单，在仅复制插件包的临时目录执行其 hooks，验证技能、references 与注入脚本自包含，测试路径含空格和中文。运行 Claude 官方清单验证、Codex 原生本地市场发现（若本机能力允许），并核对 npm 打包内容。

所有验证均不修改使用者全局插件安装、权限或信任设置；发布、推送不属于本轮。
