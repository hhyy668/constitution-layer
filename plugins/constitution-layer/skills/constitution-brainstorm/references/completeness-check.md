# 完备性检查

智能体只检查立场，不自行推断或改写价值条款；可转录开发者已确认的文本。
发现缺陷 → 提示开发者决定修订，已有文件不因另一份缺失而重写。

## 四类缺陷

| 缺陷 | 判定 | 例 |
|---|---|---|
| **无判定性** | 无法验证是否违反 | 「要写好代码」 |
| **内部矛盾** | 同场景下两条规则要求相反行为 | 既要求「宁慢勿缺」又要求「快速交付」 |
| **不可执行** | 缺「谁在什么条件下做什么」 | 「要谨慎处理数据」 |
| **空转条款** | 覆盖不到任何实际决策场景 | 列了但从来不会被触发的规则 |
| **冗余** | 重复、解释性文字、同一规则多处表述 | 同一条禁止在两节各写一遍 |

## 可执行形式

纸面判定容易放水，每类缺陷用一个动作来查：

| 缺陷 | 动作 | 不通过的信号 |
|---|---|---|
| 无判定性 | 拿一个具体改动，一分钟内判断是否违反 | 判不出，或两人判法不同 |
| 内部矛盾 | 对每条取舍轴，问「两边都适用时偏向哪边」 | 答「都要」 |
| 不可执行 | 补齐「谁、什么条件、做什么」三要素 | 任一要素缺失 |
| 空转条款 | 请开发者举一个本项目会触发它的具体场景 | 举不出 |
| 冗余 | 删掉这句，规则含义是否不变 | 不变即冗余，提议合并或删除 |

红线与取舍分类用事故测试：违反后是回滚还是要解释。回滚进宪法，解释进心智模型。

## 交叉检查

单文件通过 ≠ 通过。必须交叉：

1. 宪法「必做」引用的判据，心智模型里是否真的定义了
2. 心智模型是否与宪法冲突（级别：宪法赢，但冲突要报出来）
3. 声明的硬依赖是否存在；可选增强缺失明示后继续
4. 篇幅是否在开发者确认的建议值内（默认宪法 40 行、心智模型 80 行）；超出先压缩再谈放宽
5. 是否把排序偏好误写成绝对红线；修改是否有开发者明确授权与文本确认
6. 现有指令文件（CLAUDE.md、AGENTS.md 等）与宪法的优先级是否声明

## 回测

从 git log 取最近两个有争议或返工过的改动，用两份文件判一次：
红线是否能排除错误方案，取舍是否能在合法方案间给出排序。
判不出的记为缺口，由开发者决定补或留；不替人补。

## 检查报告格式

```
宪法：N 行 / 建议 X          心智模型：N 行 / 建议 Y

| 文件 | 缺陷类型 | 位置 | 说明 |
|---|---|---|---|

回测：改动 1 → 结论 / 缺口；改动 2 → 结论 / 缺口

结论：可提交 / 需修订
```

无缺陷时明确写「未发现缺陷」，不要留空。
