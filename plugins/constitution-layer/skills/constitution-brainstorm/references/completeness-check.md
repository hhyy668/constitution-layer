# 完备性检查

智能体只检查立场，不自行推断或改写价值条款；可转录开发者已确认的文本。
发现缺陷 → 提示开发者决定修订，已有文件不因另一份缺失而重写。

## 四类缺陷

| 缺陷 | 判定 | 例 |
|---|---|---|
| **无判定性** | 无法验证是否违反 | 「要写好代码」 |
| **内部矛盾** | 同场景下两条规则要求相反行为 | 既要求「宁慢勿缺」又要求「快速交付」 |
| **不可执行** | 缺「谁在什么条件下做什么」 | 「要谨慎处理数据」 |
| **空转条款** | 覆盖不到任何实际决策场景 | 列了但从来不会被触发的规则 |

## 交叉检查

单文件通过 ≠ 通过。必须交叉：

1. 宪法「必做」引用的判据，心智模型里是否真的定义了
2. 心智模型是否与宪法冲突（级别：宪法赢，但冲突要报出来）
3. 声明的硬依赖是否存在；可选增强缺失明示后继续
4. 篇幅是否在上限内
5. 是否把排序偏好误写成绝对红线；修改是否有开发者明确授权与文本确认

## 检查报告格式

```
宪法：N 行 /上限 X          心智模型：N 行 / 上限 Y

| 文件 | 缺陷类型 | 位置 | 说明 |
|---|---|---|---|

结论：可提交 / 需修订
```

无缺陷时明确写「未发现缺陷」，不要留空。
